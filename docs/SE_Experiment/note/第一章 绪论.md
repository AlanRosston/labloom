# Chapter 1 导论
## 1.1 软件概论

**软件 (software)** 被定义为**程序**，**数据**和**相关文档**的集合，它的特点是：
* 抽象，无实体
* 无明显制造过程，无备件
* 手工制作，成本昂贵

软件的质量分为：
* **产品质量**。用户看的是功能、故障、性能、易用性等**外部特性**，开发者看的是**代码，可维护性**等内部特性
* **过程质量**。如 CMM, ISO 9000, SPICE 等标准
* **商业质量**。用 
$$
ROI = \frac{\text{收益} - \text{成本}}{\text{成本}} \times 100 \%
$$
进行量化

## 1.2 软件质量

**McCall 模型**：把用户看到的**外部质量**，通过层层分解，对应到开发者能控制的**内部属性**，最后落到可度量的指标上。是一种**软件质量模型**

细节参见 [[McCall 模型]]

软件不会磨损，但是会**退化 (deteriorate)**。其原因是需求不明确，多次变更请求，缺乏变更控制等

| 对比项    | 硬件               | 软件                            |
| ------ | ---------------- | ----------------------------- |
| 本质     | 物理产品             | 逻辑产品                          |
| 产生方式   | 制造（manufactured） | 开发（engineered）                |
| 失效曲线   | 浴盆曲线             | 理想下降曲线 / 实际锯齿状上升              |
| 是否磨损   | 会（物理老化）          | **不会**                        |
| 失效原因   | 物理损耗、材料疲劳        | 设计缺陷、变更引入的错误                  |
| 退化原因   | 磨损、环境（灰尘、温度、振动）  | **多次变更**导致组件交互出错              |
| 备件     | 可更换损坏零件          | **没有备件**，每个故障都是设计/代码错误，需要修改设计 |
| 复制成本   | 每件都要制造，有成本       | 复制几乎零成本，成本集中在开发               |
| 组件化程度  | 大量使用标准件          | 多数仍是定制开发，复用不足（对应课件练习第 5 题）    |
| 质量控制重点 | 制造过程             | 设计与开发过程                       |

针对软件退化，参见 [[Lehman 定律]]


## 1.3 软件危机与解决

按照功能，软件可以划分为：
* **系统软件**，如操作系统内核
* **支撑软件**，如选课系统，银行管理系统
* **应用软件**，如淘宝、京东等

开发和维护过程中产生的严重问题称为**软件危机**，表现为：
* 用户需求不明确，变更多
* 开发进度难以控制
* 软件成本日益增长
* 质量差，维护困难
其产生的原因是：
* 软件开发无计划性
* 软件需求不充分
* 开发过程无规范
* 软件产品无评测手段
要解决它们，途径是：
* 加强软件**开发过程管理**
* 推广使用开发软件的成功技术与方法
* 开发和使用好的软件工具
> 软件工程的本质是管理学

| 类型  | 迷思（Myths）   | 事实                    |
| --- | ----------- | --------------------- |
| 管理  | 进度落后就加人     | Brooks 定律：给延期项目加人只会更晚 |
| 客户  | 软件灵活，变更容易   | 变更成本随时间急剧上升           |
| 开发者 | 程序跑起来才能评估质量 | 正式技术评审比测试更能发现某些错误     |
