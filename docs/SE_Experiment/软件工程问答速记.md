# 知织（Labloom）软件工程问答速记

依据 note/ 的前三章笔记，对照当前代码。重点用 Feed 模块回答，路径均相对于项目根目录。

## 1. 实体类、边界类、控制类分别是什么？

| 分类 | 最关键的项目例子 | 回答要点与代码位置 |
| --- | --- | --- |
| 实体类<br>Entity | FeedSource（来源）<br>FeedItem（条目） | 表示业务信息，如来源名称、地址、条目标题和已读状态。<br>shared/types/feed.ts |
| 边界类<br>Boundary | FeedView.svelte<br>SourceForm.svelte | 展示订阅列表、接收筛选和来源表单输入。<br>renderer/components/Feed/ |
| 控制类<br>Control | FeedService | 组织来源校验、刷新、去重保存和阅读状态更新。<br>main/feed/service.ts |

记法：实体是“保存什么”，边界是“通过什么操作”，控制是“谁组织流程”。实体概念在这里由 TypeScript 类型和数据库记录表达，边界由 Svelte 组件表达。

再举一个控制类：Startup，负责恢复、创建和打开工作区（main/startup/startup.ts）。

## 2. 用一个真实用例，把三类职责串起来

例子：刷新订阅。参与者是用户和外部订阅来源；前置条件是已打开工作区且已有来源；结果是保存新条目并更新列表。

点击刷新 → FeedView → window.api.feed.refresh() → IPC → FeedService.refresh() → fetchFeed() 获取条目 → SQLite 保存；界面再调用 getState() 读取列表。

定位：preload/index.ts 是通信桥；main/feed/ipc.ts 接收调用；main/feed/service.ts 组织业务；main/feed/parser.ts 获取和解析内容。

## 3. 属性、操作和封装，怎么用代码解释？

属性：FeedItem.title、isRead 描述条目信息。操作：FeedService.refresh()、setRead() 执行刷新和状态修改。封装：pending、database 是私有成员，外部通过公开方法使用服务。

## 4. 哪些类关系最容易举例？

| 概念 | 项目例子 |
| --- | --- |
| 关联 | FeedItem.sourceId 对应 FeedSource.id：一个来源对应多条条目。 |
| 组合的例子 | 当前来源表的外键设置 ON DELETE CASCADE，删除来源会同时删除其条目，体现生命周期依赖。 |
| 依赖 | FeedService 使用 fetchFeed 和数据库对象完成刷新与保存。 |
| 泛化／类型特化 | Paper、EditablePage 都基于 Page 泛型定义。代码使用类型特化表达共性，不是 class extends 继承。 |

定位：shared/types/feed.ts、shared/types/Paper.ts、shared/types/EditablePage.ts、main/feed/service.ts。

## 5. 功能需求、非功能需求和实现方案有什么区别？

| 类别 | 一句话回答 | 本项目例子 |
| --- | --- | --- |
| 功能需求 | 系统做什么。 | 用户可以刷新订阅、筛选条目、标记已读。 |
| 非功能需求 | 系统做得怎样。 | 需求报告中冷启动≤5秒、搜索首批结果≤1秒，属于性能目标。 |
| 实现方案 | 具体怎样实现。 | 采用 Electron、Svelte 和 SQLite；界面通过 IPC 调用主进程。 |

需求分析先讲用户目标；设计再讲模块、接口和技术选择。

## 6. 顺序图和状态图，分别画什么？

顺序图看“谁先调用谁”：可画第2节的 FeedView → FeedService → 获取与保存流程。状态图看“同一对象怎样变化”：阅读器是 empty → loading → ready，加密 PDF 会进入 password 状态。

## 7. 信息隐藏、高内聚、低耦合如何对应？

信息隐藏：界面只通过 FeedAPI 调用 getState、refresh 等操作；SQL 和去重规则集中在 FeedService 内。高内聚：parser.ts 专门处理抓取和解析。低耦合：FeedView 依赖 FeedAPI 接口，通过参数接收具体实现。

定位：shared/types/feed.ts、renderer/components/Feed/FeedView.svelte、main/feed/parser.ts。

## 8. 如果老师问“五类设计类”，怎么举例？

| 设计类类别 | 关键例子 |
| --- | --- |
| 用户界面类 | FeedView：展示条目并接收用户操作。 |
| 业务领域类 | FeedSource、FeedItem：订阅来源与条目的业务数据。 |
| 过程类 | FeedService：完成订阅刷新等业务流程。 |

## 9. 软件质量、测试和过程，用什么回答？

质量与测试：条目不重复、已读状态能恢复，是可检查的外部行为。configs/feed.test.js 有解析函数测试，也有“保存—关闭—重开工作区”的集成测试。模块分工清楚则有利于维护。

软件与工作产品：程序是 main/、renderer/ 中的代码；数据是工作区中的 SQLite 和附件；相关文档在 docs/。需求说明书、设计说明书和测试脚本都是工作产品。

配置管理与裁剪：Git 的 commit 记录代码和文档版本；本次实验围绕六个基本用例和必要的 UML 模型开展需求分析，体现任务集裁剪。
